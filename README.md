# ระบบเสนอความต้องการพัสดุ — สำนักงานสาธารณสุขจังหวัดนครนายก

ระบบบันทึกคำขอใช้พัสดุ ตรวจสอบโดยเจ้าหน้าที่พัสดุ ติดตามความก้าวหน้าการจัดซื้อจัดจ้าง
พร้อมแดชบอร์ดเชิงลึกและการส่งออกข้อมูล

- **หลังบ้าน**: `code.gs` — Google Apps Script Web App ทำหน้าที่เป็น JSON API เชื่อมกับ Google Sheet
- **หน้าบ้าน**: `index.html` + `assets/` — เว็บ static deploy ผ่าน Vercel ใช้งานได้ทุกอุปกรณ์

---

## 1. ขั้นตอนการทำงานของระบบ

| ลำดับ | ผู้ดำเนินการ | การกระทำ | สถานะคำขอ |
|---|---|---|---|
| 1 | กลุ่มงานผู้ขอ | บันทึกคำขอ + แนบ **แผนการใช้งบประมาณ (บังคับ)** และเอกสารอื่นตามจำเป็น | `ร่าง` |
| 2 | กลุ่มงานผู้ขอ | ส่งให้เจ้าหน้าที่พัสดุตรวจสอบ | `รอพัสดุตรวจสอบ` |
| 3a | เจ้าหน้าที่พัสดุ | พบข้อผิดพลาด → เขียนเหตุผลและส่งกลับ | `ส่งกลับแก้ไข` |
| 3b | กลุ่มงานผู้ขอ | แก้ไขแล้วบันทึก → ระบบสร้าง **เวอร์ชันใหม่** (v2, v3 …) อัตโนมัติ เก็บของเดิมไว้เป็นประวัติ | `ร่าง` (v ใหม่) |
| 4 | เจ้าหน้าที่พัสดุ | ตรวจสอบถูกต้องครบถ้วน | `ผ่านการตรวจสอบ` |
| 5 | กลุ่มงานผู้ขอ | ดาวน์โหลด PDF และ Word ไปเสนอในระบบ Smart Office (SMO) | `ผ่านการตรวจสอบ` |
| 6 | เจ้าหน้าที่พัสดุ | นพ.สสจ. ลงนามใน SMO แล้ว → แนบเอกสารที่ลงนามครบทุกแผนก ระบบ **ล็อกข้อมูล** ทันที | `อนุมัติแล้ว` 🔒 |
| 7 | เจ้าหน้าที่พัสดุ | บันทึกความก้าวหน้าการจัดซื้อจัดจ้างเป็นระยะ | `อยู่ระหว่างจัดซื้อจัดจ้าง` |
| 8 | เจ้าหน้าที่พัสดุ | บันทึกขั้นตอน "รายงานผลการตรวจรับ" | `ดำเนินการแล้วเสร็จ` |

**การปลดล็อก**: เจ้าหน้าที่พัสดุปลดล็อกได้เอง แต่ต้องระบุเหตุผล และระบบบันทึกลง log ทุกครั้ง

### ขั้นตอนความก้าวหน้า (12 ขั้นตอน)

แผนจัดซื้อจัดจ้าง → TOR/ราคากลาง → รายงานขอซื้อขอจ้าง → แต่งตั้ง คกก.พิจารณาผลฯ/ตรวจรับพัสดุ →
ร่าง/ประกาศประกวดราคา → หนังสือเชิญชวนเสนอราคา → รายงานผลการพิจารณา → ประกาศผู้ชนะการเสนอราคา →
เว้นระยะอุทธรณ์ → ลงนามสัญญา → บริหารสัญญา → รายงานผลการตรวจรับ

แก้ไข/เพิ่มขั้นตอนได้ที่หน้า **ตั้งค่าระบบ → ตัวเลือกในระบบ → ProcurementStage**

### บันทึกย่อ 3 ระดับ

| ช่อง | ใครเห็น |
|---|---|
| หมายเหตุ | ทุกคนที่มีสิทธิเห็นคำขอนั้น |
| note พัสดุ | เฉพาะเจ้าหน้าที่พัสดุที่ผู้ดูแลระบบกำหนดไว้ |
| my note | เฉพาะเจ้าของบันทึก และผู้ดูแลระบบ (Super Admin) |

## 2. การติดตั้งหลังบ้าน (Google Apps Script)

1. เปิด Google Sheet ฐานข้อมูล → เมนู **ส่วนขยาย → Apps Script**
2. วางเนื้อหาไฟล์ `code.gs` ทั้งหมดลงในไฟล์ `Code.gs` (แทนของเดิม) แล้วบันทึก
3. ตรวจสอบค่า `CONFIG.SPREADSHEET_ID` ให้ตรงกับ Sheet ที่ใช้
4. รันฟังก์ชัน `setupSupplySystem` หนึ่งครั้งเพื่อสร้าง/ปรับโครงสร้างตาราง และอนุญาตสิทธิที่ระบบขอ
   - ตรวจสอบเขตเวลาของโปรเจกต์ให้เป็น **(GMT+07:00) Bangkok** ที่ ⚙️ การตั้งค่าโปรเจกต์ มิฉะนั้นวันเวลาที่บันทึกจะคลาดเคลื่อน
5. กด **Deploy → New deployment → Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
6. คัดลอก URL ที่ลงท้ายด้วย `/exec`

> ทุกครั้งที่แก้ `code.gs` ต้อง **Deploy → Manage deployments → แก้ไข version เป็น New version** ไม่เช่นนั้นหน้าบ้านจะยังเรียกโค้ดเดิม

### ตารางในฐานข้อมูล

| แผ่นงาน | หน้าที่ |
|---|---|
| `UserAccounts` | บัญชีผู้ใช้ (ใช้ร่วมกับระบบบุคลากรเดิม — ระบบนี้อ่านอย่างเดียว) |
| `SupplyRequests` | คำขอ (ทุกเวอร์ชัน มี `Version`, `RootRequestID`, `IsLatest`) |
| `SupplyRequestItems` | รายการพัสดุในแต่ละคำขอ |
| `SupplyInspectors` | คณะกรรมการ/ผู้ตรวจรับพัสดุ |
| `SupplyProgressLogs` | ความก้าวหน้า + บันทึกย่อ 3 ระดับ |
| `SupplyAuditLogs` | log การใช้งานทั้งหมด |
| `SupplySessions` | โทเคนเข้าสู่ระบบ (หมดอายุอัตโนมัติ 12 ชั่วโมง) |
| `setting` | ตัวเลือกทั้งหมด + รายชื่อผู้มีสิทธิ + ค่าตั้งต้นระบบ |

ระบบจะเติมคอลัมน์ใหม่ให้ข้อมูลเดิมโดยอัตโนมัติเมื่อรัน `setupSupplySystem` — ไม่ลบข้อมูลเก่า

## 3. การติดตั้งหน้าบ้าน (Vercel)

1. แก้ไฟล์ `assets/config.js` ใส่ URL ที่ได้จากข้อ 2.6
   ```js
   API_URL: 'https://script.google.com/macros/s/xxxxxxxx/exec',
   ```
2. push ขึ้น GitHub
3. ที่ Vercel → **Add New Project** → เลือก repository นี้
   - Framework Preset: **Other**
   - Build Command / Output Directory: เว้นว่าง (เป็นเว็บ static ไม่ต้อง build)
4. Deploy — ทุกครั้งที่ push ขึ้น GitHub Vercel จะ deploy ใหม่อัตโนมัติ

> ถ้ายังไม่ได้ใส่ `API_URL` ระบบจะขึ้นหน้าให้กรอก URL เองและจำไว้ในเบราว์เซอร์ของเครื่องนั้น

## 4. การตั้งค่าครั้งแรกในระบบ

เข้าสู่ระบบด้วยบัญชีที่มี Role เป็น Admin แล้วไปที่เมนู **⚙️ ตั้งค่าระบบ**

1. **สิทธิผู้ใช้งาน** — เลือกรายชื่อจาก UserAccounts
   - *เจ้าหน้าที่พัสดุ* — เห็นคำขอทุกกลุ่มงาน ตรวจสอบเอกสาร บันทึกความก้าวหน้า เห็น "note พัสดุ"
   - *หัวหน้าเจ้าหน้าที่พัสดุ* — สิทธิเท่าเจ้าหน้าที่พัสดุ
   - *ผู้ดูแลระบบ (Super Admin)* — ตั้งค่าระบบ ดู log และเห็น "my note" ของทุกคน
2. **ตัวเลือกในระบบ** — ชื่อพัสดุ หน่วยนับ แหล่งเงิน ขั้นตอนพัสดุ และการจับคู่แหล่งเงิน → ใน/นอกงบประมาณ
3. **ส่งออกข้อมูลไป Sheet ปลายทาง** — ใส่ Spreadsheet ID ปลายทาง และ API Key (ถ้าต้องการให้ระบบอื่นดึงข้อมูล)

> ก่อนกำหนดรายชื่อครั้งแรก ระบบจะถือว่าผู้ที่มี Role ขึ้นต้นด้วย `admin` เป็นผู้ดูแลระบบชั่วคราว
> เพื่อไม่ให้ไม่มีใครเข้าหน้าตั้งค่าได้เลย

## 5. การส่งออกข้อมูล

| วิธี | การใช้งาน |
|---|---|
| **Excel** | ปุ่ม 📥 Excel ที่หน้าแดชบอร์ดหรือรายการคำขอ — ได้ 3 แผ่นงาน (คำขอ / รายการพัสดุ / ความก้าวหน้า) ตามตัวกรองที่เลือก |
| **PDF / Word** | เปิดคำขอ → ปุ่ม 🖨️ PDF / Word (พิมพ์ได้หลังผ่านการตรวจสอบ) และรายงานสรุปที่หน้าแดชบอร์ด |
| **ซิงก์ไป Sheet อื่น** | ตั้ง `ExportSpreadsheetId` แล้วกด "ส่งข้อมูลออกเดี๋ยวนี้" หรือตั้งเวลาอัตโนมัติ |
| **REST API** | ให้ระบบภายนอกดึงข้อมูลด้วย API Key |

### ตั้งเวลาซิงก์อัตโนมัติ

เปิด Apps Script แล้วรันฟังก์ชันใดฟังก์ชันหนึ่งเพียงครั้งเดียว:

- `installExportTriggerHourly` — ซิงก์ทุกชั่วโมง
- `installExportTriggerDaily` — ซิงก์ทุกวัน เวลาประมาณ 01:00 น.

ข้อมูลที่ส่งออกคือ `SupplyRequests`, `SupplyRequestItems`, `SupplyProgressLogs`
(ยกเว้นคอลัมน์ `MyNote` ซึ่งเป็นบันทึกส่วนตัว)

### ดึงข้อมูลจากภายนอก

```
POST https://script.google.com/macros/s/xxxx/exec
Content-Type: text/plain

{"action":"externalData","key":"<ExportApiKey>","filters":{"fiscalYear":"2569"}}
```

## 6. รายการคำสั่ง API

ทุกคำสั่งส่งแบบ `POST` ด้วย `Content-Type: text/plain` และ body เป็น JSON ที่มี `action`
(คำสั่งที่ต้องยืนยันตัวตนต้องส่ง `token` ที่ได้จาก `login` มาด้วย)

| action | คำอธิบาย | สิทธิ |
|---|---|---|
| `ping` | ทดสอบการเชื่อมต่อ | ทุกคน |
| `login` / `logout` | เข้าสู่ระบบ / ออกจากระบบ | ทุกคน |
| `bootstrap` | โหลดข้อมูลตั้งต้นทั้งหมดในครั้งเดียว | ผู้เข้าสู่ระบบ |
| `listRequests` / `getRequest` | รายการคำขอ / รายละเอียดคำขอ | ตามสิทธิเข้าถึง |
| `saveRequest` | บันทึกคำขอ (ส่ง `submit:1` เพื่อบันทึกและส่งพร้อมกัน) | เจ้าของคำขอ |
| `submitRequest` | ส่งให้พัสดุตรวจสอบ | เจ้าของคำขอ |
| `reviewRequest` | ผ่าน/ส่งกลับ (`result: "pass" \| "return"`) | เจ้าหน้าที่พัสดุ |
| `attachApproval` | แนบเอกสารอนุมัติและล็อก | เจ้าหน้าที่พัสดุ |
| `setLock` | ล็อก/ปลดล็อก | เจ้าหน้าที่พัสดุ |
| `addProgress` / `listProgress` / `deleteProgress` | ความก้าวหน้า | ตามสิทธิ |
| `dashboard` / `publicDashboard` | ข้อมูลแดชบอร์ด | ตามสิทธิ / สาธารณะ |
| `exportRows` | ข้อมูลสำหรับ Excel | ผู้เข้าสู่ระบบ |
| `getSettings` / `saveSetting` / `deleteSetting` / `setRoleMembers` | ตั้งค่าระบบ | Super Admin |
| `syncExport` | ส่งข้อมูลไป Sheet ปลายทางทันที | Super Admin |
| `externalData` | ดึงข้อมูลด้วย API Key | ระบบภายนอก |
| `listLogs` | ประวัติการใช้งาน | Super Admin |

## 7. โครงสร้างไฟล์

```
code.gs              หลังบ้านทั้งหมด (Apps Script)
index.html           โครงหน้าเว็บ
assets/config.js     ตั้งค่า API URL และชื่อหน่วยงาน
assets/app.js        ตรรกะหน้าบ้านทั้งหมด
assets/app.css       สไตล์ รวมรูปแบบเอกสาร A4
vercel.json          ตั้งค่า deploy บน Vercel
```

## 8. ข้อควรทราบด้านความปลอดภัย

- เซสชันใช้โทเคนอายุ 12 ชั่วโมง เก็บในแผ่นงาน `SupplySessions` — รหัสผ่านไม่ถูกส่งซ้ำในแต่ละคำสั่ง
- URL ของ Web App ต้องตั้งเป็น "Anyone" เพื่อให้หน้าเว็บบน Vercel เรียกได้ การเข้าถึงข้อมูลทั้งหมดถูกควบคุมด้วยโทเคนและสิทธิผู้ใช้ในฝั่งเซิร์ฟเวอร์
- รหัสผ่านยังเก็บในแผ่นงาน `UserAccounts` แบบเดิมเพื่อให้ใช้ร่วมกับระบบบุคลากรได้
  หากต้องการเข้ารหัสรหัสผ่านต้องปรับทั้งสองระบบพร้อมกัน
- ทุกการกระทำถูกบันทึกใน `SupplyAuditLogs` พร้อมผู้ทำ เวลา และรายละเอียด
